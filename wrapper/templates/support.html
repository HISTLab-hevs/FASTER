Contribute to FASTER

FASTER is an open research platform for federated learning experimentation. Whether you are citing the platform, submitting a patch, or sharing reproducible results, every contribution helps improve the project.

How to Cite FASTER

If you use FASTER in research, cite it with the metadata in CITATION.cff at the root of the repository. GitHub turns that file into a ready-made citation under "Cite this repository", in BibTeX or APA. Record the version or commit you used in your reproducibility notes.

Current citation guidance

If your work uses the FedGP aggregation method, please also cite the paper that introduced it: doi:10.1007/978-3-031-90062-4_26.
Formal citation metadata will be added after the project has an official publication record.

Code Contributions

Engineering contributions are the backbone of FASTER. We welcome pull requests for core engine improvements, novel aggregation algorithms, UI refinements, new dataset integrations, and documentation fixes.

Submit a Pull Request

Fork the repository, create a feature branch, and open a PR against main. For significant architectural changes, please open an RFC issue first to align with the core team.

Report a Bug

Open an issue on GitHub with a minimal reproducible example, your environment details, and the observed vs. expected behaviour. Include FASTER logs where possible.

Propose a Feature

Ideas for new federated methods, evaluation metrics, or platform capabilities are welcome. Use the GitHub Discussions board or open a feature-request issue with a rationale and expected impact.

Improve the Documentation

Clear documentation lowers the barrier for adoption. Corrections, clarifications, additional examples, and translated content all count as valuable contributions.

Community

Even without writing code, you can have a tangible impact on FASTER's growth and adoption.

  • Star the repository on GitHub — it increases discoverability and signals active community interest.
  • Write about FASTER — tutorials, architectural deep-dives, or experiment write-ups on your blog, Medium, or arXiv preprint server.
  • Present at events — share results obtained with FASTER at conferences, workshops, seminars, or internal team meetings.
  • Advocate internally — champion FASTER adoption within your organisation's MLOps, research, or data science infrastructure teams.
  • Answer questions — help other users on GitHub Discussions or academic forums, reducing the support load on the core team.
